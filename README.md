# grill-me-plus

> 按轮次拷问你的产品方案或开发计划，问到没有歧义为止，最后输出一份可以直接执行的方案简报 / 开发规格。

基于 [Matt Pocock 的 grill-me](https://github.com/mattpocock/skills) 改良，面向 **AI 产品经理** 和 **用 AI 写代码做产品（vibe coding）** 的场景。

---

## 为什么要改良

原版 grill-me 只有几句规则：一次只问一个问题、每题给一个推荐答案、能查代码就查代码。它简洁好用，但有四个明显的不足：

1. **太慢**：一次只问一题，复杂方案要来回几十次
2. **不会停**：没有结束条件，也没有总结
3. **会漏项**：没有维度清单，问到哪里全靠 AI 发挥
4. **不留产出**：共识只存在当前对话里，换个会话就丢了

## 和原版的对比

| | 原版 grill-me | grill-me-plus |
|---|---|---|
| 提问节奏 | 一次一题 | 每轮 5～7 题，上限 10 题；遇到关键分叉、矛盾等 5 种情况时只问 1～3 题 |
| 回答方式 | 一个推荐答案 | 选择题 A～D / 多选题 / 填空题，⭐ 标出推荐项和理由；支持"1A 2C""全推荐"快捷回复 |
| 覆盖范围 | 无清单 | 产品清单 9 项 + 技术清单 8 项，分必填/选填，并写明每项的完成标准 |
| 适用场景 | 写代码 | 产品模式 / 开发模式 / 串联模式（从想法到开发规格） |
| 客观性 | 无规则 | 指出认知偏差、论据不足、逻辑问题；用户反驳但没有新论据时不改立场 |
| 结束 | 无 | 3 条停止条件 |
| 产出 | 无 | 方案简报 + 开发规格 + 待决事项（假设 / 风险 / 待定） |

## 安装

**方式一：skills CLI**

```bash
npx skills add https://github.com/yezhu-aipm/grill-me-plus --skill grill-me-plus
```

**方式二：手动安装**

把 `grill-me-plus/` 文件夹复制到：
- 全局：`~/.claude/skills/grill-me-plus/`
- 单个项目：`.claude/skills/grill-me-plus/`

**方式三：Claude.ai**

在设置的 Skills 页面上传 `grill-me-plus` 文件夹（打包成 zip）。

## 使用

自然说出这些话就能触发：

- "拷问我" / "grill me"
- "把我的方案问清楚"
- "压力测试一下这个计划"

想确保一定启用时，直接输入 `/grill-me-plus`。

## 一轮提问长什么样

```
📍 第 2 轮 · 必填 4/9 · 待定 5 · 本轮 3 题

🔶 Q1. 做网页还是小程序？
这题会决定：登录方式、部署方式、页面结构
- A. 网页（⭐ 推荐：你说要先发给朋友试用，链接直接能打开，门槛最低）
- B. 微信小程序
- C. 两者都做
- D. 先做 Figma 原型，不写代码

🔶 Q2. 这一版要做哪些功能？【多选】
- A. 上传成绩  B. 生成报告  C. 导出 PDF  D. 历史记录  E. 分享链接
（⭐ 推荐：A+B+C，先跑通核心闭环，D、E 放到第二版）

🔶 Q3. 第一批试用的老师大概有多少人？【填空】
例如：5 个熟人老师

回复示例：1A 2ABC 3大概10个，或者"全推荐"
```

## 最终产出

| 产出 | 什么时候有 | 用途 |
|---|---|---|
| 方案简报 | 产品模式、串联模式 | 对齐需求，给团队或面试官看 |
| 开发规格 | 开发模式、串联模式 | 交给新的 AI 会话直接开发，不需要回看对话 |
| 待决事项 | 所有模式 | 列出还没定的假设、风险和需要外部确认的事项 |

## 测试

用 Anthropic 官方的 skill-creator 做过两轮测试，测试用例在 [`grill-me-plus/evals/`](grill-me-plus/evals/)。每个用例包含用户输入（`prompt.md`）、期望结果（`case.yaml`）和逐条检查项（`graders/`）。

| 用例 | 测什么 |
|---|---|
| `vague-product-idea` | 模糊想法：第一轮的格式、题型，以及有没有识别出风险 |
| `detailed-website-chain` | 信息详细的建站需求：会不会重复提问、技术题有没有合并 |
| `biased-overscoped-plan` | 带偏见、范围过大的计划：客观性、模式判断 |
| `final-output-after-rounds` | 问完后输出：简报、规格、待决事项是否完整，有没有擅自加功能 |

**迭代记录**

| 轮次 | 对比 | 通过率 | 发现并修复的问题 |
|---|---|---|---|
| 第 1 轮 | v2 vs 不装 skill | 100% vs 61% | 缩量规则太容易触发、开场信息没计入进度、模式判断偏向串联、最终产出擅自加功能、篇幅偏长 |
| 第 2 轮 | v3 vs v2 | 97% vs 92% | 上面 5 个问题都已修复；第一轮从 3 题增加到 6～7 题，最终产出不再擅自加功能 |

说明：每个版本每个用例只跑了一次，检查项中有一部分是格式要求，所以通过率只作为参考。
